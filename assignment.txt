# Home Assignment - Junior Full Stack

Thank you for your interest in joining our team!

As part of the hiring process, we have prepared a home assignment to help us evaluate your skills in a practical way. We understand that candidates have different strengths and experiences, so we are giving you **three assignment options** to choose from. You can select the one that best aligns with your expertise and interests.

### **How It Works**

- Review the three assignment options below.
- Choose **one** assignment to complete.
- Follow the provided instructions and submit your work within the given timeframe.
- Your solution will be evaluated based on **code quality, functionality, best practices, and creativity**.

This assignment is designed to be **practical and manageable**, allowing you to showcase your skills without taking too much of your time. If you have any questions, feel free to reach out.

Good luck! We’re excited to see what you build. 🚀

### Option 1: Support Ticket Analyzer

**Task:**

Create a command-line tool or simple script that reads a JSON (or CSV) file containing a list of support tickets. Each ticket can include fields such as ticket ID, subject, description, and created_at.

**Requirements:**

- **Data Processing:** Parse the file and categorize tickets by common keywords (e.g., “login”, “payment”, “bug”).
- **Summary Report:** Output a summary with counts per category and list tickets older than a user-specified date.
- **Technologies:** Use your preferred language and basic file I/O; regular expressions or simple keyword matching are sufficient.

**What It Tests:**

Basic data manipulation, file I/O, and text processing.

### Option 2: Knowledge Base Manager

**Task:**

Develop a lightweight web application or command-line tool that simulates a support knowledge base. This knowledge base will store help articles (each with a title, content, and tags) that can be created, updated, and searched.

**Requirements:**

- **CRUD Operations:** Implement functionality to add, edit, and delete articles.
- **Search:** Allow the user to search for articles by keyword or tag.
- **Storage:** Use local filesystem storage (e.g., JSON files) or a local database instance via docker-compose.
- **Interface:** A minimal web UI (or CLI-based menu) is sufficient.

**What It Tests:**

Basic web (or CLI) development skills, CRUD operations, and simple search functionality.

- **Update Status:** Provide a simple mechanism (button or form) to change a ticket’s status.
- **Storage:** Use a local file (JSON) or a lightweight database (e.g., SQLite via docker-compose).

Basic full-stack development, REST API (or similar), simple front-end display, and file-based or local database storage.
